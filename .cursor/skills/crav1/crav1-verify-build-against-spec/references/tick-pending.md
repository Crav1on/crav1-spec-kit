# Tick pending

**Tick pending (1.136.0).** That status is not Not implemented. The reply's Run next skips every task the ready check already counts as done (ticked, or recorded merged) and names the first task that can start. `verify.md` has no `Next:` line (1.169.0). The open checkbox stays a Gap. After a passed check the report may offer the tick on its own line: `Tick pending: T2. Say yes to tick [x] in tasks.md.` Tick that one row only after that yes. Do not re-implement. The offer is an alternative exit. It does not replace the Run next entry for tasks that can start.

**Verified on branch (1.176.0).** Evidence passed on a work branch that is not merged yet, and the row is still `[ ]`. Write the branch and the pull request in the evidence, from git, for example `pass at 61dc1ce on feat/orders-cicd, PR 82 open`, with `verify_rows.py set --file <spec-folder>/verify.md --task <T#> --status "Implemented, verified on branch" --evidence "<evidence>"`. Never write **Not implemented** with passing evidence. A check that can only pass after the merge (it says `(after merge)` or `merged into develop`) is pending, not failed. The ready check says `verified on <branch>, waits for PR <n> to merge`, and the row becomes **Implemented, verified, tick pending** once the merge is recorded.
