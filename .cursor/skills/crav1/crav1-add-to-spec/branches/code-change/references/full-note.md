# Code into specs: **Full note (1.61.0)**

Part of `branches/code-change/BRANCH.md`, read only when that file sends you here. Moved word for word in 1.107.0; the rules are unchanged. Paths in backticks are relative to the skill folder.

## Full note (1.61.0)

Every run writes **one note** for the change, as this skill's `references/notes.md` says. It holds the full commit messages, the list of changed files, and the diff hunks the kept quotes come from. Path `docs/notes/YYYY-MM/YYYY-MM-DD-<slug>.md` by the **commit date** (the newest commit of a range). Front matter `kind: code change`, `source` the SHA or range, and `commits:` the short SHAs this note imported, oldest first, without merge commits (`commits: [155b5c4, 2c0e1a9]`). The body starts with one commit line per imported commit, `<short sha> <author date> <subject>` (1.64.1), before the full messages, files and hunks. After a narrowed overlap, `source` and `commits:` hold only the new commits. When the change came from a pull request (named, or the one pull request of the branch), the note also gets `pr_note:` with the PR note's path (1.65.0).

**PR note (1.65.0).** Write or reuse the pull request's note as `references/notes.md` **PR note** says: one note per pull request, `kind: pull request`, keyed by `source: PR <n> <repo URL path>`, filed by its created date, a new `## Description as of <date>` section only when the description changed, after the personal-data and secrets check and the four image options. A spec point taken from the description gets `Full source:` with the PR note's path, and the slug goes in its `used_by`. Each kept quote is followed by `Full source: docs/notes/YYYY-MM/<file>.md`, and the slug goes in `used_by`; a matching parked spec gets nothing and goes in `waiting_for`. The same commit or range again, or a change whose commits are all already in notes (by SHA or the same change by `git patch-id`), is `already imported on <date> as <note>`, reuse or skip; never a second copy. One note may feed several specs: reuse adds the other spec to `used_by`. Run `scripts/notes_index.py` after the note changes. Do not hand-edit an index.
